## Failed Attempts

- Normal `bruin validate` initially failed because BigQuery still had old schemas without the new event columns. Resolved by materializing root assets with `--no-validation` and then rerunning normal validation.
- First `raw.marketing_funnel` rebuild failed because a CTE and column were both named `paid_clicks`; BigQuery resolved the bare name as a row struct. Renamed the CTE and reran successfully.
- DAC validation initially failed because this workspace has upstream `dac` 0.2.2, not the local fork described in `DAC.md`. The installed schema rejects `hideName`, `yLabel`, `yRight`, `yRightLabel`, and `seriesNames`. Resolved by removing fork-only properties and using only schema-supported widget fields.
- After adding filters to shared query files, browser widgets failed with `missing variable 'filters'` because the Sales/Overview dashboard YAML files had not yet defined matching filters. Resolved by adding the filters to every dashboard that calls those query files and rerunning `dac check`.
- One filtered daily sales query initially failed BigQuery grouping because the formatted day label referenced `order_date` directly after aggregation. Resolved by aggregating by `order_day` in a CTE and formatting the label in the outer SELECT.
- During the GA4 audit, `raw.ga4_events` initially failed validation because a CTE and numeric column were both named `order_attempts`; BigQuery resolved the bare name as a row struct. Renamed the CTE and reran successfully.
- The first hourly outage audit showed GA4 hourly purchase events were mathematically distributed while Shopify order timestamps were uniform across the day. Resolved by shaping 2026-02-04/2026-02-05 Shopify timestamps and deriving hourly GA4 purchase events from paid Shopify orders.
- New Stripe-dependent assets initially failed validation before `raw.stripe_payment_intents` existed in BigQuery. Resolved by materializing the new root Stripe table first, then `raw.stripe_refunds` and `reports.rpt_payment_reconciliation`.
